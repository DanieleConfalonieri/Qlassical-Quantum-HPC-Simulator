# Scientific programming exam review

Reviewed 4 October 2026; submitted revision `ec55f2b`; feedback branch `feedback`. Source changes in this review are comments only. Findings distinguish reproduced failures from static analysis. No numerical grade is assigned because no marking rubric was supplied.

## Evaluation of the work

An ambitious, substantially implemented C++20/OpenMP project with a compact IR, specialized quantum kernels, bounded dense fusion, useful layer separation, and a broad test suite. These demonstrate worthwhile scientific-programming and HPC skills. **The hardware-aware execution path is not currently correct**, so its reported speedups cannot establish a valid optimization. Numerical input validation, block execution semantics, and experimental methodology also need improvement. Overall: promising implementation and strong scope, but major revision is required before accepting the optimized simulator as scientifically reliable. Prioritize C1, then C2–C4, before further performance claims.

## Correctness

1. **C1 — Critical: windowing changes the computed state.** The [backend GLOBAL_SWAP case](include/backend/cpu_openmp_engine.hpp#L219) is a no-op, while the [windowing pass](include/middleware/middleware.hpp#L857) rewrites gate operands. Reproduced with `QuantumCircuit(3).x(2)`, fusion disabled and `k_safe=1`: amplitude 1 becomes one instead of amplitude 4. Further, the pass discards its final mapping; implementing swaps alone will not restore the logical state layout expected by callers or subsequent blocks. Execute physical swaps and either undo the final permutation or explicitly carry mapping through execution and output. Test optimized versus original execution on arbitrary initial states, measurements, and multiple blocks. Disable windowing until this is fixed.
2. **C2 — High: invalid state dimensions and values.** [Dimension calculation](include/backend/cpu_state_vector.hpp#L58) shifts without checking the word width. UBSan confirms `initialize(64)` has undefined behavior on this 64-bit host. Check representability, vector capacity and byte-size limits before allocation. The [normalization test](include/backend/cpu_state_vector.hpp#L109) accepts NaN (reproduced), since comparisons with NaN are false. Require finite amplitudes/norm. Both initialization overloads change qubit metadata before operations that can throw; commit metadata only on success.
3. **C3 — High: malformed custom gates are accepted.** [unitary()](include/frontend/frontend.hpp#L344) accepts duplicate target indices (reproduced with a 4×4 identity on `{0,0}`); gather/scatter assumes distinct targets and can produce wrong results or overlapping parallel writes. Check the original span length before narrowing to `uint8_t`, validate uniqueness and bounds before storing the matrix. Public IR also bypasses builder validation: validate arity, engine qubit bounds and matrix dimensions at the execution boundary, or document/enforce a trusted-IR contract. Pool lookup currently relies on an assertion that disappears in Release.
4. **C4 — High: block boundaries lose execution context.** [State-only transfer](include/frontend/circuit_runner.hpp#L180) destroys earlier measurement records and replaces the RNG with the default-seeded generator in the move-state constructor. Two blocks measuring the same deterministic qubit return one record instead of two (reproduced). Reuse one engine or transfer the complete execution context. `run()` also consumes shared circuit builders; document/enforce one-shot ownership or support repeatable execution explicitly.
5. **C5 — Medium: rare measurement outcomes are misnormalized.** [Probability clamping](include/backend/cpu_openmp_engine.hpp#L647) replaces a legitimate probability below `1e-12`; the collapsed state's norm squared becomes `p/1e-12`, rather than one. This is a static numerical finding, not a sampled rare-event reproduction. Normalize by actual selected subspace mass; handle invalid/zero mass explicitly.
6. **C6 — Medium: barriers do not implement their contract.** [Global barriers](include/frontend/frontend.hpp#L375) have zero arity and therefore create no DAG dependencies. Reproduced: `h(0); barrier(); x(0); h(0)` becomes one fused gate plus a barrier, crossing the scheduling boundary. Lists longer than four are silently truncated, including validation. Give global barriers explicit semantics in DAG construction and support or reject oversized lists.
7. **C7 — Medium: the named QFT is not a QFT.** [Generator](include/frontend/circuit_generators.hpp#L62) uses CNOT instead of controlled phase rotations. On two-qubit input basis index 1 it returns `(1,1,-1,-1)/2`, rather than the complex Fourier phases (up to sign/order convention). Implement controlled phases or name/document this as a synthetic connectivity workload.

## Efficiency and algorithm suitability

For `n` qubits and `G` gates, state storage is Θ(2^n) complex doubles, approximately `16·2^n` bytes. Specialized fixed-arity gates take Θ(2^n) work each; a dense `k`-qubit gate costs Θ(2^(n+k)), with Θ(4^k) matrix storage. The four-qubit fusion cap sensibly bounds arithmetic and scratch space. Exact state vectors are appropriate for general small/medium noiseless circuits; stabilizer simulation would scale better for Clifford-only workloads, while tensor networks may suit low-entanglement circuits. These alternatives change the supported workload or performance tradeoff.

- **E1:** [vector::resize](include/backend/cpu_state_vector.hpp#L64) constructs/zeros complex elements on the allocating thread before the OpenMP loop. Consequently, the claimed parallel first-touch placement is not established. `std::vector` also provides no 64-byte alignment guarantee. Use a deliberate allocation/parallel construction strategy with correct object lifetimes, thread binding, and measured page placement. The second zeroing pass adds bandwidth cost.
- **E2:** [Safe-window comparisons](include/middleware/middleware.hpp#L90) treat `k_safe` as an inclusive maximum index, while topology computes a qubit count and window growth uses a count. Use indices `[0,k_safe)`. NUMA capacity alone is not the actual per-thread/page-placement boundary; calibrate against allocation layout, affinity and measured transfer costs.
- **E3:** DAG construction is O(G+n) at fixed arity, but [fusion membership searches](include/middleware/middleware.hpp#L561) can make fusion traversal quadratic in long narrow circuits. Use indexed membership marks. Dense matrix products add O(8^k) per merge; pool storage retains original matrices. Benchmark compilation cost and total memory, not only execution. An OpenMP serial cutoff can reduce launch overhead on small states.
- **E4:** [Weak scaling](benchmarks/bench_scaling.cpp#L107) holds state memory per thread constant, but gate count grows with `n`, so work per thread is not constant. Report both. Windowing benchmarks execute the incorrect C1 path and omit the missing swap cost. Rerun after correctness fixes; use repeated measurements, dispersion, affinity/compiler metadata and saved machine-readable results. [Plot data](benchmarks/scaling_plot.py#L16) are embedded literals; the checked-in `bench.txt` contains strategy comparisons, not these scaling runs. Performance curves alone do not identify memory bandwidth as the bottleneck.

## Comments, organization and modern style

Comments explaining bit-index insertion, matrix order and ownership are useful. Many banners and line-by-line narrations add bulk without explaining invariants. Correct the stale 64-byte/first-touch claims, the statement that matrix indices are flat-array offsets (they index metadata), the rvalue-only `release()` claim (the method is not ref-qualified), and the README's suggestion of available MPI/GPU execution (these are stubs). The [“wait!” matrix derivation](tests/middleware/test_fusion_math.cpp#L38) and inconsistent ket ordering should be replaced by a checked, concise derivation.

The frontend/middleware/backend split is good, but the 882-line original middleware header combines graph construction, matrix algebra, policies and rewriting. Separate these concerns; share the duplicated clustered-circuit generator between benchmarks. Keep hot kernels inline where useful and move orchestration into implementation files. Include standard headers directly (`<array>`, `<algorithm>`, `<cstdint>`, etc.), use consistent formatting and fixed-width types, and use `std::bit_width` for exact power-of-two dimension metadata. [CPUHwlocTopology](include/middleware/hw_topology.hpp#L97) owns a raw hwloc handle but is implicitly copyable: delete copying or wrap it in unique RAII ownership to prevent double destruction. Make [native ISA/fast-math](CMakeLists.txt#L18) opt-in and target-scoped; retain a strict floating-point reference configuration. Gate tests/benchmarks behind CMake options instead of requiring all development dependencies for library consumers.

## Validation and limits

GCC 13.3 Debug build, Eigen, OpenMP and hwloc: all targets compiled and **102/102 CTest cases passed**, with `OMP_NUM_THREADS=2`. Catch2 initially could not write to the sandbox's `/run/user/1000`; setting `XDG_RUNTIME_DIR=/tmp` resolved this environmental issue. Commands:

```sh
cmake -S . -B /tmp/qlassical-review-build -DCMAKE_BUILD_TYPE=Debug
XDG_RUNTIME_DIR=/tmp cmake --build /tmp/qlassical-review-build -j 2
OMP_NUM_THREADS=2 ctest --test-dir /tmp/qlassical-review-build --output-on-failure
```

Additional temporary C++ probes reproduced C1–C4, C6 and C7; C2's shift was checked with `-fsanitize=undefined -fno-sanitize-recover=undefined`. A deterministic seed-13 differential check of 1,000 five-qubit, 40-gate circuits (H/X/Y/Z/S/CX/RY/SWAP) matched fusion-only execution to unoptimized execution at `1e-10` amplitude tolerance. This supports fusion on that sample, not universal correctness. Current windowing tests largely check rewritten instructions, not final physical states. No Release accuracy validation, large-memory scaling or cluster benchmark rerun was performed; absence of syntax failures in this build is not a portability guarantee.
